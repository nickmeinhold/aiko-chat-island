# Key-name inventory for deploy/secrets/*.env.sops — NAMES ONLY, never values.
#
# WHY THIS EXISTS. The secrets are SOPS *binary* blobs (a real-newline PEM is not
# legal dotenv), so a future diff can show THAT a file changed but not WHICH key —
# a permanent loss of review surface on a public, immortal artifact. This manifest
# buys it back: a PR that adds, removes or renames a key changes THIS file visibly,
# in cleartext, where a reviewer can see it.
#
# IT LEAKS NOTHING NEW. Every name here is already public in docker-compose.yml,
# which has always been committed (ISLAND_SIGNING_SEED appears there 5 times).
# That settles a tension between the reviewer's own rounds — 'key counts are
# reconnaissance' vs 'commit a manifest' — on the first one's own terms.
#
# VERIFIED BY: ./deploy/verify-secrets.sh --deep  (needs a key; not run in CI).
# CI cannot decrypt, so CI checks only that this file is well-formed and covers
# every island. The binding check is the deep one, and it must be run before
# merging any change to a *.env.sops.
