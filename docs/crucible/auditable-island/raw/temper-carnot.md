DISSOLVE

Tier 2 and Tier 3 collapse under the threat model. `DESIGN.md §3` admits the fatal property: “an island cannot be made to sign” and absence of a signature “proves nothing.” Since the operator is explicitly the adversary, the adversary simply runs old code, strips signatures, or signs only benign cases. A mechanism that only convicts an upgraded operator who voluntarily keeps incriminating output enabled is not adversarial auditability. It defends mainly against bugs and confused honest operators, not the hostile operator this project names.

Tier 1 survives, but not as “auditable island.” Echoing the row `client_msg_id` is a real position-binding fix: `FOLD.md F-2` says the write path enforces `origin.client_msg_id == frame_client_msg_id`, storage has `UNIQUE(channel_id, client_msg_id)`, but `message_view()` omits the row value. Adding it lets clients compare row `client_msg_id` against the signed origin’s `client_msg_id`. That is actionable. But it is just message integrity plumbing, not reputation dissolution.

The privacy claim in `DESIGN.md C-5` is under-reviewed and likely unsafe as stated. A client-chosen opaque ID can contain UUIDs stable across chats, device/session prefixes, timestamps, counters, database IDs, or library fingerprints. Echoing it forever to every channel member creates a cross-channel correlation handle if clients reuse or structure IDs badly. Given `RESEARCH-crosstab.md` cites a decided constraint that the island must not learn friend/call relationships, this needs a wire-contract rule: high-entropy random per-message IDs only, no embedded account/device/channel/time semantics, and no reuse across channels. Without that, Tier 1 may fix integrity by expanding metadata leakage.

The reframe is mostly honest, but the final proposal retreats past usefulness. The forge correctly killed the original “auditability dissolves reputation” slogan: `RESEARCH-priorart.md` shows deployed transparency systems retain admission layers, and `DESIGN.md §6` admits “age-of-externally-attested-history” becomes reputation. But “sign the ack” is not the smaller true answer; it is what remained after discarding the only load-bearing property from Kelvin’s spark. The design should have stopped at “KT later; fix position binding now.”

Tier 0 is not evasion. `RESEARCH-crosstab.md C8` and `DESIGN.md §2` show Andy’s originating question still has not been answered. Putting that first is a real process finding. It just is not part of the engineering design.

What to do instead: ship Tier 1 only after a privacy spec for `client_msg_id`, and post Design 06 back to Andy. Do not build signed acks or the conformance prober as an auditability feature. Keep the real long-run path as Design 06 KT with explicit gates: rotation/revocation, multi-device identity, app verification, and either an admitted auditor/public anchor or an honest statement that N=2 has no split-view protection.
