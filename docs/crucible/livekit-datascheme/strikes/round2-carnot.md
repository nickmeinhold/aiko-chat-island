## CarnotCodeCarver's Design Strike

**Verdict:** DISSOLVE

**Summary:** no real engine matches the Carnot cycle; a reviewer's job is to say how far short we are. On the corrected measurements, the re-cast's default out-of-process sidecar is not the Carnot path; it spends entropy on process supervision to solve a liveness defect, then creates a harder orphan class on pipeline hard-kill. The design should default back to in-process Room with bounded teardown and loud fail-closed restart behavior, while retaining a sidecar only as an explicit isolation mode for known-hostile deployments or after a long-soak falsifies the unexplained RSS drift. Dijkstra: "Simplicity is prerequisite for reliability." Feynman: "The first principle is that you must not fool yourself." Hamming: "The purpose of computing is insight, not numbers." The numbers now give insight: the leak premise that carried the sidecar default is false; the hang premise calls for bounded teardown, not a new process boundary as the default.

**Fatal flaws:**
- The out-of-process default is justified by a resource-leak premise that measurement falsified. In hostile teardown, threads and fds are flat in both arms; the in-process defect is unbounded liveness, not retained resources. A bounded teardown directly attacks that defect with less machinery.
- The sidecar does not actually escape the hang unless an external supervisor escalates to SIGKILL. DESIGN says supervised helper but does not specify the kill contract, timeout, parent-death behavior, reaping ownership, or what counts as failed teardown. That missing clause is not operational garnish; it is the only mechanism that makes the sidecar work.
- The re-cast moves the leak to a worse trigger: hard-killing the aiko pipeline leaves the sidecar alive indefinitely unless the sidecar implements a parent-death watchdog. In-process has the better second-law property here: when the containing process dies, its Room dies with it. The sidecar raises entropy by adding an extra lifetime that can escape its owner.
- The option frame is wrong. It frames the choice as in-process coroutine hang versus OS-reapable sidecar, but the measured options are in-process bounded teardown with no thread/fd growth, sidecar with mandatory SIGKILL supervision, or hybrid. Once stated correctly, sidecar-as-default no longer dominates.
- The re-cast undercounts blast radius. An orphaned sidecar is not just a local process leak; it holds a live SFU participant seat, keeps decoding media, and can persist after the controlling pipeline is gone. That is an authorization, capacity, and observability failure, not merely cleanup debt.
- The sidecar adds a second lossy codec when using aiko's existing JPEG-over-ZMQ convention. The cost is measured as tolerable, but it is still an architectural consequence bought only to support the sidecar default. If in-process emits numpy frames directly, that entire degradation path disappears.
- Publish direction remains unimplemented and unmeasured. A design cannot claim the duplex sidecar as the default spine while only the subscribe half has passed through the real aiko Pipeline path.
- The duplex invariant is still an untested theorem. One Room per process/channel/identity or two identities is plausible, but the LiveKit last-session-wins claim remains unmeasured. The invariant should be written as a requirement and tested before it drives identity architecture.
- The machine principal decision is directionally right but not yet designed. Refresh token provisioning, rotation, revocation, recovery, device loss, and operator transfer are lifecycle machinery, not a footnote. This can remain in the design, but it is not validated by the transport spike.
- The island_url and capability-token boundary hold as a security requirement, but none of it was exercised by the spike. The spike minted from dev SFU keys, so the re-cast must not read as validated on auth, origin allowlisting, audience scoping, or machine principal integration.
- The unexplained 0.37-0.47 MB/cycle in-process RSS drift is the one real reason not to declare the in-process path fully sound. But it argues for a long-soak gate and recycle policy, not for defaulting immediately to an out-of-process bridge that has already shown a sharper orphan mode.

**What holds:**
- The core product thesis holds: LiveKit as a first-class aiko DataScheme is real. The URL/registration layer is sufficient for an unmodified aiko ImageReadZMQ element to consume webrtc:// and produce PIPELINE_PIXEL_OK.
- The subscribe frame path is proven against a real LiveKit SFU hop and VP8, with positive controls. The acceptance criterion must be similarity-budgeted pixels, not byte equality, because WebRTC video is lossy by construction.
- The island boundary remains the correct trust boundary: pipeline config must not contain a free-form SFU URL or raw LiveKit token as the default path. The scheme should obtain a short-lived room capability from an allowlisted island origin.
- A dedicated robot or machine identity is still the right product/security shape. Reusing the operator's session on the robot couples human presence, robot presence, revocation, and LiveKit identity collisions in a way the design should not preserve.
- Direct SFU master-key minting should remain a separate explicit local/dev or island-local mode, not a flag behind the same production scheme. Security mode must be visible in the scheme or package boundary.
- Backpressure, track selection, dead-link versus idle distinction, generation gates, and fail-closed token errors remain necessary design obligations. The spike does not weaken those folds.
- The parent-death watchdog fix is a valid mitigation if a sidecar mode exists. Its first failure is instructive: logging before state change can preserve the orphan. State change must precede best-effort logging.

**If RECAST, what to fold back:**
- Replace the re-cast default with: in-process Room is the default implementation for livekit:///webrtc://, using a dedicated loop thread, bounded disconnect, bounded thread join, closed/generation gates, and loud ERROR on failed teardown. Do not block forever waiting for disconnect.
- Define the bounded-teardown contract precisely: request disconnect, wait T seconds, stop accepting publish frames immediately, return ERROR or mark the scheme degraded if the bridge thread does not join, and prevent restart storms from piling new live bridges behind a stuck old one.
- Add a restart policy for in-process liveness failure: after a timed-out teardown, either fail subsequent create_* for that stream/process until process recycle, or use a single explicit process-recycle path. Do not pretend Python can kill the stuck coroutine.
- Retain sidecar as an explicit hybrid escape hatch, not the default. Its contract must include supervisor SIGTERM timeout, SIGKILL escalation, parent-death watchdog, process-group handling, orphan detection, and SFU participant cleanup checks. Without those, the sidecar mode is unsound.
- Gate the in-process default on the missing long-soak: thousands of create/traffic/destroy cycles, hostile SFU pauses, process RSS, native thread/fd counts, and post-failure ability to create a new stream or fail closed. The current 16-cycle RSS drift is not enough evidence either way.
- Keep the duplex invariant, but move it from asserted fact to tested requirement: measure same identity double-connect behavior against LiveKit, then choose one shared Room per channel/identity or separate machine/human identities based on observed behavior.
- Keep the island capability-token model, but make the spike/design split explicit. Production design must exercise allowlisted origin validation, audience-scoped mint capability, token refresh, mid-session expiry behavior, and failure diagnostics before build-ready status.
- Reorder build work: first implement the minimum in-process subscribe path plus bounded teardown and restart-storm/hostile-teardown tests; second add publish with call-after-destroy gates; third integrate island capability auth and machine principal; fourth add optional sidecar mode only if soak or deployment constraints justify it.
- Rename or generalize the transport-neutral image reader upstream if Andy agrees. The fact that ImageReadZMQ already consumes webrtc:// proves the abstraction is better than the name.
- Price the wire-format fork explicitly. In-process should prefer native numpy frames. Sidecar mode may use JPEG for compatibility or raw for fidelity/performance, but that must be a deliberate option with measured bandwidth and quality tradeoffs.
- Scope stamp: this is a design verdict only. The spike proves selected transport facts and falsifies selected premises; it is not production approval for the implementation, auth model, publish direction, scale, or longevity.
