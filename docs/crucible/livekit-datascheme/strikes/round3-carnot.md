## CarnotCodeCarver's Design Strike

**Verdict:** RECAST

**Summary:** No real engine matches the Carnot cycle; a reviewer's job is to say how far short we are. The recast correctly inverts the default back to in-process and names the hang as a liveness defect, but it still spends too much confidence from too little measurement. Bounded teardown is a necessary clock, not yet a sufficient safety proof; the host-wide invariant is asserted while its enforcement is process-local; and the auth/identity half remains almost entirely theoretical. This is a DESIGN temper only: the spike is not production code, publish direction is unimplemented, duplex collision is untested, and island integration is untouched. Round 3 verdict: RECAST, narrowly, with merge blockers promoted into hard acceptance gates rather than another architectural flip.

**Fatal flaws:**
- D1 proves only that abandoned teardown did not grow measured Python threads or fds across 8 hostile cycles. It does not prove the abandoned Room releases SFU participant state, ICE/native allocations, decoder state, subscriptions, TURN allocations, server-side bandwidth, or RSS. The unexplained ~0.4 MB/cycle drift is not a footnote; it is the second law showing entropy somewhere below the instruments.
- D1's restart-storm policy says fail closed while a prior bridge is unreaped, but the design does not define the observable state machine strongly enough: what marks unreaped, what clears it, what survives exceptions, and what happens after process crash/restart while the SFU still believes the old participant exists? Hamming's question applies: what are the important problems you are not working on? This is one.
- D2 states a HOST-WIDE invariant, then installs a module-local registry. That registry cannot see two pipeline processes, a restarted process, or another runtime on the same host. The text tries to dissolve this through identity allocation, but that just moves enforcement into D4, which is still open. Until machine identity allocation is real and uniqueness-scoped per bridge instance, the invariant has no reliable owner.
- D2's phrase 'host-wide' may be the wrong thermodynamic boundary. The collision domain is really LiveKit `(room, identity)` across all clients, not one host. If two hosts run the same robot credential, or a cloned disk boots twice, a host-local registry is perfectly reversible on paper and useless in the universe.
- D3/D4 are load-bearing and unexercised. The transport half has measurements; the security half has prose. A design that forbids raw SFU tokens but has no proven headless machine-principal lifecycle is not build-ready, because the fallback pressure will be to smuggle master-key minting back in as 'temporary'. Dijkstra: simplicity is prerequisite for reliability; an unbuilt credential story is not simple.
- D5's pipeline/robot-host default is the right default, but it does not discharge blast radius by itself. It relies on fate-sharing with process death, while the main identified defect is not death but partial liveness failure: abandoned coroutines and still-live SFU state. The recast correctly excludes island-local v1, but it should say the default is safe only under bounded participant TTL and successor-creation proof, not merely because the process is on a robot.
- D7's `fidelity` parameter smells like a knob where a contract should be. If in-process always yields numpy/lossless frames and sidecar serialization is opt-in, URL consumers should not be asked to choose an implementation tax unless the choice changes semantics they actually understand. Otherwise nobody sets it, defaults become policy, and the system silently encodes a measurement-vs-inference decision.
- The build order still defers auth and machine principal until after publish direction. That is the wrong option-frame for upstreaming a transport whose central security claim is island-mediated capability minting. Build can prototype transport first, but merge readiness cannot sequence security after bidirectional media and still call the design coherent.

**What holds:**
- The reversal from sidecar-default to in-process-default is still the correct direction. The measured leak premise behind round 1 failed, and the sidecar created a harder orphan class on hard-kill. The Carnot-efficient move is still to delete the process machinery from the default path.
- The liveness invariant itself is right: no pipeline lifecycle operation may wait indefinitely on SFU liveness. Every network await needs a deadline. Feynman's warning fits here: what I cannot create, I do not understand. The spike created the hang and measured it; that is real progress.
- D6 as opt-in isolation is coherent. Native crash isolation, import isolation, and gateway constraints are legitimate reasons for a sidecar, provided SIGKILL escalation, parent-death reaping, child-local disconnect bounds, and no reconnect-after-parent-death are mandatory.
- Separating `webrtc://` from `livekit-local://` is correct. Transport naming should not bind the API to a vendor, and master-key minting must remain syntactically separate from island-capability auth.
- The pipeline/robot host is the correct v1 default compared with island-local. It narrows blast radius and avoids putting a media bridge inside the gateway/chat failure domain.
- The scope stamp in the recast is honest: publish direction, duplex collision, island auth, machine principal, and long soak are explicitly not proven.

**If RECAST, what to fold back:**
- Promote D1 from 'bounded teardown is sufficient' to 'bounded teardown is necessary, pending resource-envelope proof'. Acceptance must include RSS, native heap if available, SFU participant count, subscriptions, TURN/ICE allocation indicators, reconnect/successor creation, and long hostile soak. Threads/fds alone are not enough.
- Replace the D2 enforcement story with two layers: process-local registry for intra-process source/target sharing, plus identity allocation/lease as the true cross-process and cross-host owner. If machine identity is not implemented, same-identity collision remains a hard blocker.
- Define the abandoned-Room state machine: OPEN, CLOSING, ABANDONED, REAPED, DEGRADED. Specify who transitions each state, what is persisted, what blocks successor create, and what timeout or SFU observation clears the block.
- Make LiveKit participant TTL / server-side cleanup part of the contract, not an assumption. If the design depends on SFU eventual cleanup, measure and bound it.
- Change D7 from a consumer knob to named transport profiles unless real users choose it: default in-process raw/numpy; sidecar jpeg only when using compatibility ZMQ image elements; raw sidecar only with an explicit media type. Do not expose entropy as a decorative setting.
- Move G4/G5 earlier in merge readiness: no production `webrtc://` merge without exercised island origin allowlist, capability-scoped token mint, refresh/expiry behavior, and dedicated revocable machine principal. Transport-only can remain a spike branch, not the candidate design.
- Final round discipline: do not flip back to sidecar-default. Recast the remaining flaws as gates and ownership boundaries. The design survives only if it stops treating unmeasured resources and unbuilt identity as prose-covered constants.
