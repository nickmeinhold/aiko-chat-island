## Tesla, the Arc-Prophet's Design Strike

**Verdict:** RECAST

**Summary:** You minted a telco switch in one island's SQLite, announced it with an empty signed ping, and called it an object — at 3, the column has three writers; at 6, the camera still has two rooms; at 9, the federation has no call at all.

**Fatal flaws:**
- **The synthesis is a single-home superstition.** "The invite says a call started; the island says which call" assumes one mouth. Two islands are already live. Bob's home has no row. GET is 404. Fail-open rings him into the *eternal* channel room while Alice sits in `call:<ulid>`. You did not avoid #3170's wire cost — you pushed it into a dual-room migration that production will run the week the first island ships. At 100 homes, a parameterless invite in *federated signed history* pointing at *unfederated local state* is not an object. It is a service. When the island dies, the transcript still says "a call started here" and nothing in the universe can name it. `kCallInviteBody` stays shut, so you can never backfill identity into the only layer that survives a dead operator. *"The present is theirs; the future, for which I really worked, is mine."* You built the present of one box and spent the future of the network.
- **The unique index is a channel-shaped mutex whose key is `ended_at IS NULL`.** Three writers, one bit, all monotonic, never back. That is not redundancy; that is a fuse. (1) Zombie live row — webhook dropped, nobody answers so reconcile never runs, TTL mis-set or sweep asleep — and POST is *idempotent-by-liveness*: it returns the corpse with `joined: true`. LiveKit auto-creates on join. The glare fix becomes a permanent "join the empty grave." No new call can be minted until a human DELETEs. (2) Late `room_finished` after a hangup-and-recall: call 1 reaped, call 2 live, the only live row is call 2. The design never says webhooks are addressed `room → call_id`. If the handler finds "the live call on this channel," a 3am recall is a cross-call kill. (3) Forged or merely *early* `room_finished` (SFU compromised, or just LiveKit's "no guarantees") unlocks the mutex, a new POST mints call 2, and every subsequent "ask the island" follows the rotated pointer into a different room while bodies remain in call 1. You already know the webhook JWT does not name an island. What you did not price: **monotonic end + unique slot + ask-the-island is a forced call-rotation primitive**, and the client is specified to trust the slot.
- **One number cannot be both the stuck-ring scythe and the long-call ceiling.** Last webhook on a healthy two-hour call is the last *join*. `room_started` / `participant_joined` / `participant_left` / `room_finished` — there is no heartbeat in the four. TTL-from-last-webhook hangs up working calls, frees the mutex, and reintroduces glare as call 2. TTL-from-empty never fires when `participant_left` is the packet that was dropped — the exact bug, wearing `GET /call`. Step 1 *ships this contradiction* with no webhooks at all: liveness = "younger than the TTL," so the first independently-useful increment is a hard cap on call duration equal to the ring-stop timer. You rejected #3159 to avoid island→SFU on the 1/s path, then designed a liveness triad that cannot see emptiness without `ListParticipants`. The outbound call returns, just ashamed, on the sweep.
- **Reconcile activates RoomService — a different animal from minting a join JWT.** Token minting is a signature. `ListParticipants` is admin. Same key, shared project, 100 islands: the first outbound SFU call is the moment every island can `ListRooms` the federation. A leaked island env is no longer "forges media tokens." It is a live directory of every `call:<ulid>` on the wire, then a token into each. The open variable "webhook on island vs media companion" is not a deployment footnote. LiveKit speaks to *one* URL. That URL is the 101st island — a central call-lifecycle control plane you have not drawn. Compromise the SFU (or the companion) and `ended_at` is written *as truth* into every island ledger the fanout can reach. Before, a bad webhook was a transient occupancy lie. After, it is a durable CDR mutation that unlocks the mutex.
- **You accidentally incorporated a phone company.** `started_by`, `started_at`, `ended_at`, `invite_msg_id`, participant counts — that is a call-detail record, unsigned, uncascaded (FK off), undeleted, sitting on independently-operated SQLite for a year and a decade. Disk is noise. The costs that hum: (1) no retention, no user-deletion cascade, `started_by` and `invite_msg_id` become ghosts; (2) two authors for one fact — the signed invite (loser of the glare race still announced "I started a call") and the row (`started_by` = the POST that won) — and missed-call rendering will believe the row; (3) a malicious operator does not need to invent new crimes — they *export who called whom and how long*, they hold the mutex on a channel forever, they insert a row with `invite_msg_id` NULL; (4) if GET `/call` is ever allowed to *start* a ring, the consent spine leaves the signed message and moves into a writable table. The design must forbid that in verbs, not in hope. Two production operators already hold this ledger the moment step 1 lands.
- **A call that spans two islands is not an edge case. It is the product.** Channel messages federate. The call row does not. The unique index cannot see the other home. Two live calls, two rooms, both honest. `video-token` is `/v1/calls/{call_id}` with a bare ULID and no island prefix — global name, local lookup. The client is told never to parse rooms and never told which host to ask. Group calls (the future this object is supposed to unlock) make the barge-in default: membership + idempotent-by-liveness = join the one mutex, never start a side-call. You deferred consent to #2731 while pouring the mold that makes barge-in the only shape.
- **POST `/calls` already returns `room`, while the identifier table swears the client meets `room` only on the token response.** You were just bitten by an identifier that leaked across a column the client never sees. Two sources for the room name, plus the v1 channel-scoped token still minting `room_for_channel`, is six ways to light a camera into the wrong cavity. The moved gate is a rewritten gate; the moved *room* is a rewritten join.

**What holds:**
- Server-minted ULID + `UNIQUE (channel_id) WHERE ended_at IS NULL` is the only shape that can *see both candidates and pick one*. Derivation stays dead. Purity cannot arbitrate. That metal is good.
- The client must never construct or parse a room name. Existence-hiding 404, 503-when-unconfigured, `participants` as a count, `Cache-Control: no-store`, DM-only until selective subscription exists.
- Do not reopen `kCallInviteBody`. Do not put camera-lighting in `kind` (`signingBytes` still does not cover it). Forging *start* must remain a signed message.
- Webhooks as non-authority is the right *direction*. They just must not be a writer of the mutex bit.
- Build step 1 without touching the SFU is the right incision — if liveness in that step is *not* a duration TTL pretending to be emptiness.

**If RECAST, what to fold back:**
- **Kill the synthesis as a shipping claim.** Either put `call_id` in a *new* signed field (the door on the old body stays shut; history going forward can name the object), or scope this increment in writing: *same-island DMs only; fail-open MUST NOT fall back to `room_for_channel` once the caller minted a `call:` room; mixed-version = no media, not two rooms.* Cross-island / 100-island is a different design: home resolution, webhook fanout, and what a dead island leaves in the transcript.
- **Webhook is a hint, never a writer of `ended_at`.** Only two writers: (a) reconcile (`ListParticipants` / empty-room) at answer *and* on a slow sweep, (b) an explicit user hangup. Address every SFU event by invertible `room → call_id`, never "the live row for this channel." Price RoomService as admin-API activation against a shared project — not as "one extra HTTP call."
- **Split the number.** `empty_reap` (short; only when occupancy is *known* 0) ≠ `max_duration` (long; safety cap). Step 1 uses neither as a stand-in for the other: crude liveness is `ended_at IS NULL AND occupancy_unknown`, and the unique index must have a *break-glass* (owner hangup, or sweep that *confirms* empty) so a zombie cannot hold the channel forever.
- **Name the CDR.** Retention, user-deletion, what `invite_msg_id` does when the message is taken down (today: nothing — state that), `started_by` is island-asserted not federated-signed, GET `/call` is never a ring trigger, POST `/calls` does not return `room`.
- **Draw the 101st island or refuse the shared SFU.** One webhook URL for N operators is a control plane. If you will not design it, the island half cannot claim liveness, and you are back to reconcile-only — which is #3159 with a row in front of it. That is an honest smaller design. It is not this one.

*"If you want to find the secrets of the universe, think in terms of energy, frequency and vibration."* The frequency is a late webhook after a recall, on the second island, during a call that lasted longer than the ring TTL. The glass is already humming. Do not build on this until the object can die without locking the channel, travel without asking a ghost, and end without trusting a god you do not isolate.
